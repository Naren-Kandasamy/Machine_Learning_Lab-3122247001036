\section{Objective}
In this experiment, I wanted to try out Logistic Regression and Support Vector Machines (SVM) to classify emails as spam or ham using the Kaggle Spambase dataset. I also tested out a few different SVM kernels (Linear, Polynomial, RBF, and Sigmoid) to see which one works best, and used RandomizedSearchCV to tune the hyperparameters for both models.

\section{Problem Statement}
The main goal is to accurately tag an email as "Spam" ($1$) or "Ham" ($0$). The input is a dataset with 57 numerical features that mostly just count how often certain words and characters show up in an email. The idea is to get the best possible classification metrics (like Accuracy and F1-Score) while making sure the models don't take forever to train.

\section{Exploratory Data Analysis}
When looking at the data, I noticed there were a few more ham emails than spam emails. Because of this slight imbalance, I realized I couldn't just rely on standard accuracy to tell me if the model was doing well; I needed to look at the F1-Score too. Also, since the features are just word frequency counts, they really needed to be scaled so the models would treat them fairly.

\section{Data Preprocessing}
\begin{itemize}
\item \textbf{Feature Scaling:} I made sure to standardize all the features using \texttt{StandardScaler} so they all had a mean of zero and a variance of one. This is super critical for SVMs because they rely heavily on physical distances between data points, and it also helps Logistic Regression converge faster.
\item \textbf{Sparsity Management:} Because this dataset is basically a list of word counts, I didn't bother trying to fill in missing values with averages. If a word frequency is zero, it just means the word wasn't in the email.
\item \textbf{Train-test split:} I split the dataset into Training, Validation, and Testing sets. I made sure to use a stratified split so the percentage of spam emails stayed the same across all three sets.
\end{itemize}

\section{Machine Learning Algorithm}

\textbf{1. Logistic Regression:}
\begin{itemize}
\item \textbf{How it works:} It calculates the probability that an email belongs to a certain class using a logistic (sigmoid) curve. If the probability is over 50\%, it calls it spam.
\item \textbf{Math behind it:} $P(Y=1|X) = \frac{1}{1 + e^{-(\beta_0 + \beta_1 X)}}$
\item \textbf{Pros:} It's really easy to interpret, it gives you actual probability percentages, and it runs incredibly fast even on big datasets.
\end{itemize}

\textbf{2. Support Vector Machine (SVM):}
\begin{itemize}
\item \textbf{How it works:} It tries to find the best possible line (or hyperplane) that separates the spam emails from the ham emails with the widest margin possible.
\item \textbf{Math behind it:} It minimizes $\frac{1}{2} ||w||^2 + C \sum \xi_i$ while keeping the data points on the correct side of the margin.
\item \textbf{Kernels:} If a straight line can't separate the data, the "kernel trick" temporarily bumps the data into a higher dimension to find a curve that can separate it.
\end{itemize}

\section{Discussion}
One of the most interesting things I found was that the simple Linear Kernel actually beat the more complex non-linear kernels (like Poly and Sigmoid) by a pretty wide margin (about 92.7\% accuracy compared to 84.3\%). This pretty much proves that word-frequency text data is usually linearly separable if you have enough dimensions. After tuning, both Logistic Regression and SVM ended up with very similar accuracy scores (around 92.5\%), but Logistic Regression trained way faster. The cross-validation scores proved that these results were solid and the models weren't just overfitting to the training set.

\section{Conclusion}
Overall, this lab showed how effective both Logistic Regression and SVM can be for NLP classification tasks. Testing out the different SVM kernels really highlighted that for this specific type of word-frequency data, a Linear Kernel is definitely the way to go. Both models were great at catching spam, but Logistic Regression was much faster and gives you nice probability percentages, while SVM offered a slightly better overall generalization based on the cross-validation scores.
